# 物理表 ↔ 契约字段映射（v1）

> 结论（M1 评审口径）：**服务器 `data_model` 库现有 7 张物理表是 v1 环境事实源**。不修改共享表结构、不执行 `schema.sql` 中的 ALTER/DROP；后端按物理列适配，对外 API 保持《API契约-v1》字段名。
>
> 核对时间：2026-11-13 13:36（Asia/Shanghai）
> 核对方式：后端元数据接口实时读取 `192.168.10.11:3306/data_model` 的列与类型；`SHOW INDEX` 读取索引。
> 本文只记录差异，**未对物理库做任何结构变更**。

## 1. 总览

| # | 物理表 | 用途 | 与 `schema.sql` 的差异数 |
|---|---|---|---|
| 1 | `data_model_data_source` | 数据源连接信息 | 2 列改名、1 列取值枚举不同 |
| 2 | `data_model_flow` | 编排任务主体（dag_json） | 无 |
| 3 | `data_model_flow_run` | 任务级执行记录 | 2 列改名、2 列物理独有、缺 `update_time` |
| 4 | `data_model_node_field` | 节点输出字段快照 | 1 列改名、缺 `is_dirty` / `update_time`、唯一键缺失 |
| 5 | `data_model_node_run` | 节点级执行记录 | 1 列改名、2 列物理独有、缺 `update_time`、唯一键缺失 |
| 6 | `data_model_run_log` | 执行日志明细 | 缺 `log_time`（用 `create_time` 代替）、缺 `update_time` |
| 7 | `data_model_schema_cache` | 远端表结构缓存 | 1 列改名、缺 `cached_at`、多 `db_name` |

### 2.4 `data_model_node_field`

| 物理列 | 类型 | API 字段 |
|---|---|---|
| `id` | bigint | — |
| `flow_id` | bigint | `flowId` |
| `node_id` | varchar(64) | `nodeId` |
| `field_name` | varchar(128) | `fieldName` |
| `field_type` | varchar(64) | `fieldType` |
| `ordinal` | int | `fieldOrder`（**改名**） |
| `create_time` | datetime | — |

- **缺 `is_dirty`**：Schema 漂移标记无落库载体，v1 无法持久化“上游已变更需复核”。已记为 **M4 前置项**（执行引擎做漂移检测前需定方案：加列或独立表）。
- 缺 `update_time`。
- 只有普通索引 `idx_node_field_node(flow_id,node_id)`，**无唯一键** `uk(flow_id,node_id,field_name)`；回填时应用需先删后插或自行去重。

### 2.6 `data_model_run_log`

| 物理列 | 类型 | API 字段 |
|---|---|---|
| `id` | bigint | — |
| `flow_run_id` | bigint | `flowRunId` |
| `node_id` | varchar(64) | `nodeId` |

### 2.7 `data_model_schema_cache`

| 物理列 | 类型 | API 字段 |
|---|---|---|
| `id` | bigint | — |
| `data_source_id` | bigint | `dataSourceId` |

## 3. 索引差异

| 物理表 | 物理索引 | `schema.sql` 期望 |
|---|---|---|
| `data_model_data_source` | `uk_data_source_name(name)` | `uk_ds_name(name)` |
| `data_model_flow` | `idx_flow_name(name)` | `idx_flow_name(name)` |
| `data_model_flow_run` | `idx_flow_run_flow(flow_id)`、`idx_flow_run_time(start_time)` | `idx_fr_flow`、`idx_fr_status(status)` |
| `data_model_node_field` | `idx_node_field_node(flow_id,node_id)` | 同名普通索引 + `uk_nf_flow_node_field(flow_id,node_id,field_name)` |
| `data_model_node_run` | `idx_node_run_flow(flow_id,node_id)`、`idx_node_run_run(flow_run_id)` | `uk_nr_run_node(flow_run_id,node_id)` |
| `data_model_run_log` | `idx_run_log_run(flow_run_id,node_id)` | `idx_rl_run`、`idx_rl_run_node` |
| `data_model_schema_cache` | `uk_schema_cache(data_source_id,table_name)` | `uk_sc_ds_table` |

索引差异**不阻塞 v1 读写**：查询按现有索引执行；缺少的唯一键由应用层去重（见 2.4、2.5）。

## 4. 对后续里程碑的影响

| 项 | 影响 | 处理 |
|---|---|---|
| `node_field.is_dirty` 缺失 | Schema 漂移无法持久化，M4 漂移告警无载体 | M4 前置：定方案（加列或独立 `node_field_dirty` 表），不在 v1 数据源域处理 |
| `run_log.log_time` 缺失 | 日志时间为秒级 | 前端按秒展示；如需毫秒，M4 再评估 |
| `schema_cache.cached_at` 缺失 | 用 `update_time` 作 TTL 基准 | 现有实现已如此，无影响 |
| `node_field` / `node_run` 无唯一键 | 并发重跑可能产生重复行 | M4 执行引擎写入前先按业务键删除旧行（事务内） |
| 契约索引名不同 | 无 | 不改名，SQL 不依赖索引名 |

## 5. 本轮适配状态

- **已实现并验证**：`data_model_data_source`（CRUD + 测试连接）、`data_model_schema_cache`（表/字段缓存读写与删除清理）。
- **未实现（M3–M5）**：`data_model_flow`、`data_model_flow_run`、`data_model_node_field`、`data_model_node_run`、`data_model_run_log`；实现时按本文映射，不再改物理结构。
- API 字段一律以《API契约-v1》为准，物理列名只在 Mapper/Entity 层出现。
